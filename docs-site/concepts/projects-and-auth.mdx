A **project** is the unit of multi-tenancy in Continua. Every trace, span, session, and
ingest batch is scoped to exactly one project. Authentication determines which project a
read is bound to.

## The three ways a request gets authenticated

| Mechanism | Used by | How project_id is resolved |
| --- | --- | --- |
| **API key** (`X-API-Key` or `Authorization: Bearer`) | SDKs, ingest, the debugger UI, REST integrators | Server hashes the key (SHA-256), looks it up in `projects`, injects the owning project into context |
| **Local single-user mode** (no credentials, loopback only) | Debugger UI on the machine that runs the server, when `LOCAL_SINGLE_USER_MODE=true` | No project is bound. The `project_id` query parameter selects the project, and reads require it |
| **Public demo** (no credentials) | Read-only landing on the demo deployment | Project id is hard-coded in `PUBLIC_DEMO_PROJECT_ID` |

Both credential-free modes are opt-in via env vars, and the server refuses to start with
both on. Public demo mode serves a single read-only project to anyone. Ingest
(`/v1/ingest`) always needs an API key.

On a loopback connection, `GET /api/projects` and `POST /api/projects` work without
credentials while public demo mode is off, so a fresh install can create its first
project and receive its key.

## Lifecycle of a project

1. **Create**: `POST /api/projects` returns the project record plus the plaintext API
   key. **This is the only time the key is returned in plaintext.** Store it; the server
   only keeps the hash.
2. **Use**: clients send `X-API-Key: <key>`. The middleware in
   [`internal/api/middleware/auth.go`](https://github.com/aryanVijaywargia/Continua/blob/main/internal/api/middleware/auth.go)
   resolves the key on every request.
3. **Rotate**: `POST /api/projects/{id}/rotate` invalidates the old key and returns a
   new plaintext key (also returned once). Rotation is the right tool for suspected key
   compromise.
4. **Update metadata**: `PATCH /api/projects/{id}` for renames, description changes.
5. **Delete**: `DELETE /api/projects/{id}` soft-deletes the project.

See the [Managing projects guide](/guides/managing-projects) for end-to-end how-to.

## Project scoping on reads

These rules apply to the trace, session, and engine data endpoints. The project-management
endpoints under `/api/projects` do not take or check `project_id`.

API-key and public-demo requests are always **Bound** to their project. Every data read,
including all `/v1/engine/*` reads, is filtered to that project. Requesting an id that
belongs to another project returns `404`.

On an API-key request, a `project_id` query parameter must match the key's project.
A mismatch returns `403 project_scope_mismatch`.

Local single-user requests carry no bound project. Every data read names its project with
`project_id`, and a data read without it returns `400 missing_project_id`. The UI keeps the
selected project in URL query params, so links remain shareable and the box owner can
switch projects without a new key.

The `/v1/engine/activities/*` worker surface is API-key-bound only. Credential-free
requests are rejected as unauthenticated.

## Demo mode in detail

When `PUBLIC_DEMO_ENABLED=true`:

- The server bootstraps a `PublicDemoConfig` with the configured `PUBLIC_DEMO_PROJECT_ID`
  and `PUBLIC_DEMO_LABEL`.
- The UI loads without prompting for an API key.
- Mutations are blocked: the demo is read-only.
- The Settings page redirects to `/dashboard`.

`make demo` boots a deployment with demo mode on, an idempotent demo project, and seeded
traces, which is useful for evaluating Continua without standing up your own ingest pipeline.
